# Project Architecture

Odot is a full-stack todo application with clear separation between backend and frontend:

## Backend (Go + Gin + PostgreSQL)
- **Framework**: Gin web framework with JWT authentication via Google OAuth
- **Database**: PostgreSQL with SQLC for type-safe query generation
- **Structure**: Clean architecture with handlers, middleware, and database layers
- **Key Features**: Push notifications via WebPush, OpenTelemetry tracing, structured logging

## Frontend (React + TypeScript + Vite)
- **Router**: TanStack Router with file-based routing
- **State**: TanStack Query for server state, Zustand for client state
- **UI**: Radix UI components with Tailwind CSS v4
- **Editor**: ProseMirror for rich text editing
- **Features**: Dark mode, push notifications, calendar view

## Database Layer
- **Migrations**: Located in `sql/migrations/` 
- **Queries**: SQL queries in `sql/queries/` compiled by SQLC to `internal/db/`
- **Schema**: Todos, projects, users, comments, tags, and notification systems

# Development Commands

## Backend Development
- `make dev` - Start full development environment with Docker Compose
- `make build` - Build Go application to `bin/server`
- `make test` - Run all Go tests
- `make sql-gen` - Generate Go code from SQL queries using SQLC
- `make migrate` - Run database migrations
- `make docs-gen` - Generate Swagger API documentation

## Frontend Development
- `cd ui && bun run dev` - Start Vite development server on port 5173
- `cd ui && bun run build` - Build for production
- `cd ui && bun run build:mobile` - Build mobile app with Capacitor
- `cd ui && bun run lint` - Run ESLint
- `cd ui && bun run type-check` - Run TypeScript type checking

## Database Operations
- `make db` - Connect to PostgreSQL database via Docker
- `make migrate` - Run database migrations (uses Goose)
- `make logs` - View all container logs
- `make api-logs` - View API server logs only
- `make clean` - Clean up containers and build artifacts

## Push Notifications
- `make notify` - Test push notification service
- `cmd/generate-vapid/` - Utility to generate VAPID keys for web push

## Testing & Quality
- `make test` - Run Go tests
- `cd ui && bun run lint` - Frontend linting
- `cd ui && bun run type-check` - TypeScript checking

# Key Architectural Patterns

## Backend Patterns
- **Handler Pattern**: HTTP handlers in `internal/api/handlers/` with dependency injection
- **Middleware**: Authentication, CORS, logging in `internal/api/middleware/`
- **Repository Pattern**: Database queries generated by SQLC from `sql/queries/`
  - Each SQL file in `sql/queries/` generates a corresponding `.sql.go` file in `internal/db/`
  - Custom type overrides in `sqlc.yaml` for AWS and Cloudflare credentials
- **Configuration**: Environment-based config in `internal/config/`
- **Services**:
  - Google Vision AI for image text extraction (`internal/vision/`)
  - Web push notifications (`internal/webpush/`)
  - Structured logging with Uber Zap (`internal/logger/`)

## Frontend Patterns
- **File-based Routing**: Routes defined in `ui/src/routes/` with TanStack Router
- **Component Architecture**: UI components in `ui/src/components/ui/`, feature components in `ui/src/components/`
- **Context Providers**: Auth context and theme provider for global state
- **Query Management**: Server state with TanStack Query, keys defined in `ui/src/lib/queries/`
- **Rich Text Editing**: ProseMirror integration for todo descriptions
- **Mobile Support**: Capacitor configured for iOS/Android builds

## Database Schema
- **Core Entities**: Users, Projects, Todos, Comments, Tags
- **Relationships**: Many-to-many between todos and tags, projects contain todos
- **Features**: Push subscriptions, notification queue, refresh tokens

# Development Workflow

## Adding New Features
1. **Database**: Add migration in `sql/migrations/`, queries in `sql/queries/`
2. **Backend**: Run `make sql-gen`, add handlers in `internal/api/handlers/`
3. **Frontend**: Create components, add routes, implement with TanStack Query
4. **Testing**: Add Go tests, run `make test` and frontend type checking

## Environment Setup
- Uses `docker-compose.dev.yaml` for local development with hot reload
- **Service Ports**: API (8080), Frontend (5173), PostgreSQL (5432)
- **Containers**: PostgreSQL, migrations, API server, frontend, notification processor
- Frontend proxies API requests to backend via Vite config
- Environment variables in `.env` for development configuration
- **API Documentation**: Available at `http://localhost:8080/swagger/index.html` (generated with Swagger)
- **Health Checks**: Configured for service monitoring

# Important File Locations

## Backend Files
- `cmd/server/main.go` - Application entry point with Swagger annotations
- `cmd/notify/` - Push notification batch processor
- `internal/api/routes.go` - Route registration and middleware setup
- `internal/db/` - Generated SQLC database code (auto-generated, do not edit directly)
- `internal/config/config.go` - Environment configuration
- `internal/api/handlers/` - HTTP request handlers (auth, todos, projects, push, images)

## Frontend Files
- `ui/src/main.tsx` - Application entry with router and providers
- `ui/src/routes/__root.tsx` - Root route with layout and auth context
- `ui/src/lib/api.ts` - API client configuration
- `ui/src/contexts/auth-context.tsx` - Authentication state management

## Configuration Files
- `sqlc.yaml` - SQLC configuration for database code generation
- `docker-compose.dev.yaml` - Development environment orchestration
- `ui/vite.config.ts` - Frontend build configuration with proxy settings
